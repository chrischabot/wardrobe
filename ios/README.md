# Garderobe for iOS

The native SwiftUI client of Garderobe. It is a client of the versioned API and nothing more: it holds no
recommendation, availability or style logic, sends the same domain commands as the MCP server through
`POST /v1/commands`, and shows the backend's receipts. Read this file to the end before calling anything
about the app "working": **the app itself has never been compiled or run.** There was no Mac in the build
environment. What ran, and what did not, is stated below without rounding up.

## Layout

| Path | What it is |
| --- | --- |
| `GarderobeKit/` | Swift package (tools 6.0, Swift 5 language mode, iOS 26+/macOS 15+). All client logic: contracts, API client, sign-in, persistence, the command queue, one observable model per screen, the fixture backend. Builds and tests on Linux. |
| `GarderobeKit/Sources/GarderobeKit/Contracts/GarderobeContracts.swift` | Generated from the shared zod schemas by the foundation generator; copied unmodified by `Tools/sync-contracts.mjs`. Never edit it. |
| `GarderobeKit/Sources/GarderobeKit/Resources/Fixtures/` | Five recordings of the real Worker serving the owner's real profile and inventory (see Fixtures). |
| `GarderobeKit/Sources/ContractDump/` | `garderobe-contract-dump`: drives the models offline and prints every request the client sends, for validation against the shared schemas. |
| `App/Garderobe/` | The SwiftUI app: `GarderobeApp.swift`, `Platform/` (Keychain, `ASWebAuthenticationSession`, network monitor, bootstrap), `Design/`, `Screens/`. Views read a model and call its methods; they never build a command or call the API (checked by `Tools/check-app-sources.py`). |
| `App/GarderobeShare/` | Share extension: a shared product link goes into the same investigation flow as a pasted one. |
| `App/GarderobeUITests/` | XCUITests against demo mode. |
| `App/CONVENTIONS.md` | Design and code conventions the screens follow. |
| `Garderobe.xcodeproj/`, `Config/` | The Xcode project (generated by `Tools/generate-xcodeproj.py`) and its build settings. |
| `Tools/` | The check script and its parts, the contract sync, the fixture recorder. |
| `../.github/workflows/ios.yml` | A macOS build-and-test workflow, manual trigger only. It has never been run. |

## Screens and where they come from

| Specification | Model (`GarderobeKit/Features/`) | Views (`App/Garderobe/Screens/`) |
| --- | --- | --- |
| Four destinations, capture from everywhere, settings behind the account control | `AppModel` | `GarderobeApp.swift` |
| Today: cached board first, date and weather, carousel and comparison list, Choose / Swap / Ask about this, one shoe, I wore this, day record, day brief | `TodayModel` | `Today/` |
| Wardrobe: names, search, filters, counts, grid or list | `WardrobeModel` | `Wardrobe/WardrobeScreen`, `WardrobeGrid`, `WardrobeFilterSheet` |
| Item page: image, status, availability basis, measurements, purchase, care, alterations, history with receipts, combinations, one-tap commands, feedback | `ItemModel` | `Wardrobe/Item*` |
| Optional count correction; editing several items at once | `ReconcileModel`, `BulkEditModel` | `Wardrobe/ReconcileScreen`, `Wardrobe/BulkEditScreen` |
| Temperature preview (a simulation) | `TemperaturePreviewModel` | `Wardrobe/TemperaturePreviewScreen` |
| Laundry sheet: Collected, Returned, Some items still away, Socks washed | `LaundryModel` | `Laundry/` |
| Studio: selectors, locks, For today / Explore, Find something that works, Save / Plan / Wear | `StudioModel` | `Studio/` |
| Conversation: one transcript, composer with Stop and Waiting, attachments, cards, sources, recall, try again | `Conversation/*` | `Conversation/` |
| Capture: Add an item, Identify this, What I wore; share extension | `CaptureModel`, `ShareInbox` | `Capture/`, `App/GarderobeShare/` |
| Trips and packing; returns and exchanges; projects | `TripsModel`, `ReturnsModel` | `Trips/`, `Returns/` |
| Settings: delivery and location, My style (profile, save preview, fact decisions, directions), pause and resume, connections, outfit calendar, connected assistants, inference and budgets, image review | `SettingsModel`, `StyleFacts` | `Settings/` |
| Sign-in, first use, account recovery, recovery kit, export, account deletion | `AccountModel`, `RecoveryStatusModel`, `ExportModel`, `FirstUseModel` | `Account/`, `Settings/` |

Offline behaviour is in `Commands/CommandCenter.swift` and `Persistence/`: a command gets its idempotency
key and occurrence time when the owner taps, is written to disk before it is sent, and is replayed in order
with the same key and body. A queued command is shown as waiting, never as recorded. Cached data is always
labelled with when it was last checked (`Features/Resource.swift`).

## Running the checks

One script runs everything that can run without a Mac. From the repository root:

```sh
npm ci                      # once; the contract and fixture checks use the workspace packages
SWIFT_BIN=/path/to/swift/usr/bin bash ios/Tools/check.sh
```

`SWIFT_BIN` is only needed when `swift` is not on `PATH`; `GARDEROBE_SWIFT_SCRATCH` moves the build
directory. The toolchain used here was Swift 6.4 (swift-6.4-RELEASE, Linux x86_64 from swift.org) and Node
22.23.1.

| Step | What it does | Last result here |
| --- | --- | --- |
| 1 | Prints the toolchain versions | Swift 6.4, Node 22.23.1 |
| 2 | `Tools/sync-contracts.mjs --check`: the Swift contracts are the generator's output for the live schemas | up to date (contract 1.1.0) |
| 3 | `Tools/contract-check/validate.mjs fixtures`: recordings carry the hashes of the current profile and inventory and the current contract version; every recorded answer parses with its response schema | 5 recordings, 575 answers |
| 4 | `swift build` | built |
| 5 | `swift test` | 83 tests in 15 suites passed |
| 6 | `garderobe-contract-dump` then `validate.mjs requests`: every request the Swift client produces is parsed with the shared zod schema of its route or command | 178 requests, 33 command types, 36 routes |
| 7 | The Xcode project file is what the generator produces and passes structural checks | current; 41 checks. Not opened or built in Xcode |
| 8 | `swiftc -frontend -parse` of every file under `App/` | 83 files parse. This is syntax only: no type check is possible without the iOS SDK |
| 9 | `Tools/check-app-sources.py`: the UI tests' identifier copy matches, views send no commands, banned wording, root views exist | passed |

To refresh after a contract change: `node --experimental-strip-types ios/Tools/sync-contracts.mjs`, then
`bash ios/Tools/fixtures/record.sh`, then the check script.

## Fixtures and demo mode

`Tools/fixtures/record.sh` starts the real Worker in workerd with a local D1 database, imports the owner's
real profile and inventory through the ordinary import, plays five journeys through the HTTP API and writes
down each request and answer. Nothing in an answer is edited. The journey tests replay these recordings in
strict order and fail on any request the real backend did not answer.

Three things in the recordings are not the real service, and are labelled in each file's `provenance`:
weather and Calendar are unavailable locally (boards are marked `limited`); the assistant's wording comes
from the labelled fake model (turns, runs, events and the transcript are the Worker's); sign-in assertions
are signed with the test key. Two recorded edits are fixture actions, not the owner's wishes: a rewording of
one profile sentence (then kept as it was) and a `condition` note set on the socks category.

Unit tests that need a boundary case use invented data from `Tests/GarderobeKitTests/Synthetic.swift`; every
such garment is named "Test ..." with a `gmt_test_` identifier.

Demo mode (`-GarderobeDemo` launch argument, or "Explore with demo data" on the sign-in screen) serves the
`owner-morning` recording. A permanent "Demo data. Changes are not saved." banner is shown on every
destination, and an action outside the recording is refused in plain words. `-GarderobeResetState` clears the
local caches first.

## Configuration

Set in `Config/Base.xcconfig` (or on the `xcodebuild` command line). None is a secret; the app is a public
OAuth client and holds no client secret.

| Setting | Meaning |
| --- | --- |
| `GARDEROBE_API_BASE_URL` | The deployed Worker, for example the development deployment's origin. Also sent as the OAuth `resource`. |
| `GARDEROBE_OAUTH_CLIENT_ID` | The public client registered with Cloudflare Access Managed OAuth. |
| `GARDEROBE_OAUTH_REDIRECT_URL` | The HTTPS universal-link callback registered for that client. |
| `GARDEROBE_ASSOCIATED_DOMAIN` | The domain serving `apple-app-site-association` for the callback and board links. |
| `DEVELOPMENT_TEAM` | The owner's Apple team, for signing. |
| `GARDEROBE_BUNDLE_ID_PREFIX` | `com.chrischabot.garderobe` by default; the app group and Keychain group shared with the share extension derive from it. |
| `IPHONEOS_DEPLOYMENT_TARGET` | `27.0` as the specification names iOS 27. Set `26.0` to build with a released SDK; the package and sources avoid anything newer than iOS 26. |

Against the local development Worker (`npm run dev` in `apps/worker`, token from `npm run dev:token`) the
client can send the assertion in the Access header (`TokenPresentation.header`). That live run has not been
done.

## What did not run

- The app, the share extension and the UI tests were never compiled. The package's models are compiled and
  tested; the views that call them are only parsed. Expect compile errors on first build.
- `Garderobe.xcodeproj` was never opened. It is generated in the Xcode 16+ format with synchronized folders.
- No simulator or device run: no VoiceOver, Dynamic Type, dark mode, reduced motion, increased contrast or
  reduced transparency check; no gesture, performance or memory measurement.
- No sign-in against Cloudflare Access, no Keychain, no universal link, no push or background behaviour.
- No request was sent from Swift to a running backend. The journeys replay recordings of the real Worker.
- The workflow `.github/workflows/ios.yml` was not run.

## Remaining checks on a Mac

1. Open `ios/Garderobe.xcodeproj` in Xcode 26 or later. If it does not open, regenerate with
   `python3 ios/Tools/generate-xcodeproj.py` after correcting the generator. Points the generator could not
   verify: the local package product dependency has no `package` reference; entitlement files are listed as
   membership exceptions of the synchronized folders; the project format stamps (`objectVersion 77`,
   `LastUpgradeCheck 2600`); whether the package tests appear in the scheme.
2. Set the configuration values above and build the `Garderobe` scheme for a simulator. Fix compile errors
   in `App/`. SwiftUI and UIKit uses most likely to need attention: `Tab` in `TabView` with a toolbar per
   stack; `.containerRelativeFrame` with `.scrollPosition(id:)` in the Today carousel and transcript;
   `.pickerStyle(.navigationLink)`; `ShareLink` with a `Transferable` export file; `PhotosPicker`;
   `UIPasteboard.setItems(_:options:)` for the recovery code; `.onChange(of:initial:)`; SF Symbol names
   (`washer`, `hanger`, `questionmark.viewfinder`, `thermometer.medium`).
3. Run the package tests in Xcode (`GarderobeKitTests`): they should pass on macOS as they do on Linux.
4. Run in the simulator with `-GarderobeDemo`; walk the four destinations, capture, Laundry and settings.
5. Run `GarderobeUITests` (17 tests, demo mode), including the accessibility audit.
6. Add an app icon to `Assets.xcassets/AppIcon.appiconset` (none is supplied).
7. Sign with `DEVELOPMENT_TEAM`; confirm the app group and Keychain group shared with the share extension.
8. On an iPhone against the development deployment: sign in through `ASWebAuthenticationSession` and the
   universal-link callback; relaunch and confirm the session is restored from Keychain; let the access token
   expire and confirm refresh; revoke and confirm the reauthentication path.
9. On the iPhone: Today from cache within one second; choose, swap, pick a shoe, I wore this, Undo within
   eight seconds; airplane mode, record a wear, relaunch, reconnect, confirm one receipt.
10. On the iPhone: a Studio swipe interrupted mid-gesture; locked pieces stay; local swaps feel immediate.
11. On the iPhone: Conversation while streaming, backgrounding, a network change and a backend deployment;
    reconnect while reading old messages keeps the reading position; a draft survives closing the app.
12. On the iPhone: VoiceOver through Today, Wardrobe, an item, Laundry and Studio; the largest accessibility
    text size; dark mode; Reduce Motion; Increase Contrast; Reduce Transparency; denied photo access.
13. Share a product page from Safari into Garderobe.
14. Open a board link from Calendar: it opens the app when installed, the private web board otherwise.
15. TestFlight: archive, upload, install; decide the replacement-build schedule before the 90-day expiry.

## Known gaps in the client

- Today's "another outfit" starts a run but does not follow it to completion, and options it adds do not get
  the footwear choice.
- A day brief can be set but not cleared; a day record can have garments removed but not replaced in place.
- Packing an arbitrary quantity needs a garment picker that is not built; proposed quantities can be packed.
- A return case carries no garment name, so its row is titled by kind and order and links to the item page.
- The Projects screen reads the API directly and has no cached model, so it is empty offline.
- The transcript does not load newer pages while the owner is reading history, and does not distinguish
  loading from empty.
- Receipt cards in older transcript messages do not offer Undo (the item history and the banner do).
- The image review shows the decision but not the candidate image.
- A pending owner message shows no attachment thumbnails.
- Replacing a rule after a profile edit is done in Conversation; the phone offers keep and retire for rules.
- Connection capabilities for tool services (`tools:<group>` keys) appear as toggles with the backend's
  labels; the screen has no grouping for them.
