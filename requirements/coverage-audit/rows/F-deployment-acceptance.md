# Coverage audit part F — deployment and cost, delivery and migration, acceptance evidence, setup record
Audited at commit 8445a1e.

## Summary

This audit covers 172 checklist rows (62 in section 14, 22 in section 16, 70 in section 17 and 18 in section 19): 157 verified, 15 weaker and 0 unsupported. Of the 157 verified rows, 72 are `open` and 12 are `blocked`, so they are verified only in the sense that nothing (or only what the row says) exists, and each of them is a requirement that is not implemented. By checklist status the rows are 42 implemented, 46 partial, 12 blocked and 72 open; 14 of the 42 implemented rows are weaker than claimed and should be partial, and one partial row (S19-007) claims a behaviour that no test exercises.

Nothing in scope has evidence from Cloudflare, Google, Apple, a real model or a device: at this commit there is no `deploy/` directory, and `apps/worker/wrangler.jsonc` is a local-only configuration that declares no Workflows, AI, AI Search, Browser Run, Images, Secrets Store, Flagship or Analytics binding and no development or production environment, so every deployment, cost, measurement, cutover and provisioning row simply has no evidence yet. The data migration imports two documents only (the profile and the inventory sheet), although three rows marked implemented (S16-009, S16-015, S16-016) describe a wider export and reconciliation report. Of the 28 acceptance cases in the first table of section 17, 19 have an end-to-end journey in `tests/journeys` against the real Worker on local D1 with stored receipts, 7 have only package-level tests, and 2 have no end-to-end test (device usability and cost and operations); no candidate of the evaluation corpus has been run or judged.

All file paths below are relative to the repository root `wardrobe-rebuild/`. I read the cited files with the file tools only; no test was run in this audit, so "tested" below means the test exists and its assertions are as described, not that I saw it pass.
